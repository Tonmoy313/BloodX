# ops — setup, git, gates, testing, release
Accounts (owner): GitHub (private repo) · Google Cloud staging + prod (billing + budget alert) · Neon · Cloudflare R2 · Firebase per env (FCM, App Check) · Apple Developer (APNs; iOS builds need macOS) · Google Play Console · Sentry · SMS provider (Q-007) · uptime monitor. Tools: Flutter stable, Serverpod CLI, Docker, gcloud, git, Xcode, Android Studio, a real iPhone and Android phone.
Bootstrap order (P0): repo layout → Serverpod local → env configs (secrets only from env or secret manager) → Neon (prod suspend off, staging fake-data branch, pooled/direct strings, check restore window) → Cloud Run staging (min 1, max cap, CPU always on, /health, budget alert, rollback plan) → R2 private buckets + `pending/` 24 h lifecycle → CI → Flutter shell → OTP auth (log provider) → flags → seeds → Sentry + uptime → Firebase push + App Check → git setup scripts → caps and alerts. Verify commands against current vendor docs.
Secrets and vars (names only; `.env.example`): APP_ENV, DATABASE_URL, REDIS_*, R2_*, FCM_SERVICE_ACCOUNT_JSON, SMS_*, SENTRY_DSN_*, ADMIN_ALLOWLIST · GitHub secret CLAUDE_API_KEY (security review, billed per PR) · repo vars GCP_WIF_PROVIDER, GCP_DEPLOY_SA, GCP_PROJECT, GCP_REGION, CLOUD_RUN_SERVICE, DEPLOY_ENABLED (deploy workflows do nothing until it is `true`).
Env matrix: dev local, log-only SMS, fake data · staging Cloud Run, Neon fake-data branch, test/log SMS, deploys on merge to main · prod Cloud Run, Neon main (no suspend), real SMS, deploys on version tag + manual approval in a protected GitHub environment.
Git (trunk-based): branch `task/P2-04-name` · commit starts with the task ID or docs:/chore:/ci:/fix: (hook) · never push main, force-push, or `--no-verify` (pre-push hook + branch protection including admins, because AI agents use your credentials) · one task per PR; title starts with the task ID; body `Closes #n`; ticks the phase-file box · labels phase:P0–P7, safety-critical (needs your review), blocked, decision-needed · squash merge after CI; auto-merge only docs-only PRs · issues from `scripts/gh_bootstrap.sh` (task + Q issues; milestones = phases) · tags `pN-complete` per phase, `vX.Y.Z` for production · once per clone `bash scripts/setup_hooks.sh`; install gitleaks.
Gates: commit (hooks: forbidden files, secret scan, format + analyze on Dart changes, message format) · push (not main) · PR (`ci`: secret scan, SQL/print guard, format, analyze, tests, PR title) · safety-critical PR (security-review workflow, then you) · phase exit (the Exit line of the phase file; for P5 the checklist below).
Skipped from generic web checklists: minify/split/Lighthouse (use Flutter DevTools), cookies, email verification, password hashing, RLS (F-9), load balancer/CDN/compression (F-10); webhook signatures once receipts or payments exist.
Tests: unit · service/integration (transactions, state machines, jobs) · API (auth, roles, limits) · widget · app integration · real device (push, permissions) · load. Golden path: create request → wave → pledge → check-in → arrive → both confirm → points. Per-slice test lists are in each spec file; every endpoint gets no-session, wrong-user, wrong-role, and happy-path tests.
Device matrix: low-end + recent Android (2 OS versions) · recent + older iPhone · push in foreground/background/terminated · good Wi-Fi, weak data, offline → online · bn + en on all screens, large fonts · device time zone ≠ Dhaka.
Load ([G] targets): wave send to a large simulated set (no duplicates, on time) · concurrent request lists (p95; indexes checked with EXPLAIN) · pledge race at scale · OTP burst · streaming connections · thundering herd (50+ donors open one request after a push) · cold start after idle on a throttled network.
Pre-beta checklist (P5 exit): [ ] all slice tests pass, including concurrency and recovery on staging [ ] push verified on a real Android phone and iPhone in 3 app states [ ] backups + restore drill done (Neon window verified) [ ] runbook written, contacts tested [ ] error tracking + uptime alerts reach the owner [ ] rate limits and abuse controls on [ ] role matrix tested with real admin accounts [ ] legal text installed and reviewed [ ] health wording + deferral durations confirmed by the medical contact [ ] store compliance complete [ ] flags set for the iOS review build [ ] config values signed off [ ] security review ran on all safety-critical PRs, findings resolved [ ] rollback rehearsed once [ ] cost caps, SMS spend alert, App Check enforced [ ] staging has fake data only [ ] availability defaults verified.
Release: merge → CI → staging auto-deploy → smoke (sign in, create request, pledge, check-in, release, confirm) → owner tags vX.Y.Z and approves the production environment (migrations applied first and verified) → store tracks: internal → closed beta → staged rollout → watch dashboards 1 h. Rollback: previous Cloud Run revision; migrations stay backward compatible for one release; Neon restore if a migration fails.
Beta: a few Dhaka areas, known donors, admin backup on every critical request; daily review of time-to-first-pledge, unfilled bags, releases, no-shows, push vs SMS, crashes; weekly tune config and update STATE.
Analytics events (never health data, phones, or free text): app_open, otp_requested, otp_verified, donor_setup_completed, donor_mode_joined/left, availability_set, availability_prompt_answered, readiness_passed/failed, request_created, wave_sent, push_opened, request_viewed, pledge_created, pledge_withdrawn_free, check_in_on_my_way/extended, pledge_cancelled/released, donor_arrived, donation_confirmed, rejection_reported, request_fulfilled/expired, badge_awarded, share_card_created, report_submitted.
Costs to watch: Cloud Run min instance + CPU always on, Neon plan, SMS volume (biggest swing), store fees, routing API (F-8), security-review API usage.
