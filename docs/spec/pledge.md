# pledge — matching, pledges, waves, timers, notifications (donor side)
Entities: Pledge(id, request_id, donor_id, client_request_id (unique per donor), status, committed_arrival_at (≤ needed_by), contact_share_consented (must be true), free_cancel_until, en_route_at, arrived_at, donated_at, released_at, cancel_reason, donor_confirmation, requester_confirmation (none|donated|did_not_arrive|not_eligible), created_at) · NotificationAttempt(request_id, donor_id, wave, channel, idempotency_key unique, status sent|delivered|opened|failed, responded_at, provider_message_id, created_at) · OutcomeEvent(type, actor, request_id, pledge_id, meta, created_at).
Indexes: Pledge partial unique (request_id, donor_id) where status is active (pledged|en_route|arrived) · unique(donor_id, client_request_id) · (request_id, status) · (donor_id, status). NotificationAttempt unique(idempotency_key) · (request_id, wave) · (donor_id, created_at). OutcomeEvent (request_id, created_at) · (pledge_id).
Endpoints: listRequestsForMe(cursor, limit) · getRequestDetail (hospital, ward, needed_by, bags remaining, slip thumbnail; NO requester phone) · pledge(request_id, committed_arrival_at, consent=true, client_request_id) · withdrawPledge · checkIn(on_my_way | extend_30 | cancel) · markArrived · listMyPledges · getPledge · revealContact(pledge_id) · listNotifications · markNotificationRead.
Pledge rules:
1. Needs donor_status active + readiness ≤24 h + arrival ≤ needed_by + consent.
2. Atomic: ONE transaction locks the request row, checks status and bags remaining, checks donor conflict, inserts the pledge, updates cached counts, writes an OutcomeEvent. The loser gets BAG_ALREADY_TAKEN and is offered other requests.
3. Active-pledge limit (Q-001 default): one CRITICAL or SAME_DAY at a time; SCHEDULED may coexist if arrivals are ≥4 h apart.
4. Free cancel within 10 min → withdrawn_free (no mark). Later cancel needs a reason → cancelled.
5. Check-in push 30 min before arrival: On my way / +30 min (max 2) / Cancel. On my way moves the release deadline to arrival+grace.
6. No response by arrival+grace → released: bag returns to search, requester notified at once, boosted wave (`boosted_until` = now+30 min).
7. Break rule (P-016): 3 releases or late cancels in 90 d → availability Off 30 d, shown as a friendly "take a break"; admin can lift.
Contact reveal: only with an active pledge + consent. Donor sees the requester number after pledging; requester sees the donor number once a pledge exists. Every reveal → AuditLog + OutcomeEvent. Hidden when the pledge is terminal.
Matching filters in order: component supported → group tier → eligible for alerts (donor.md) → area rule → no conflicting pledge → under notification cap → not the requester. Group tiers (P-015, medical confirms): waves 1–2 exact group; final wave of CRITICAL adds compatible groups (core table); SAME_DAY and SCHEDULED exact only. Area: waves 1–2 donors whose areas include the hospital's area; later add adjacent areas; final wave city-wide. Order: least recently notified first, random tie-break. No scores.
Waves: CRITICAL t=0 top 20 · +5 min next 50 if unfilled · +10 min all eligible in city, SMS to unopened after 5 min. SAME_DAY t=0 top 30 · +20 min next 60 · +45 min city. SCHEDULED t=0 top 30 · +3 h next 60 · +12 h city. Skip a wave once all bags are pledged. A release or cancel → immediate boosted wave for the reopened bag, then resume the schedule.
Notifications: select → NotificationAttempt (key = request_id + donor_id + wave + channel) → FCM → unopened CRITICAL after 5 min → SMS → record sent/delivered/opened/responded/failed. Caps 3/24 h (5 including critical). Quiet hours per donor.md. Copy never contains phone numbers or health details and never guilts. Requester pushes: first pledge, pledge changes, release, expiry warning, all bags filled. Donor pushes: new compatible request, check-in, requester cancelled, thank-you. Invalid tokens pruned. Provider failures: retry + circuit breaker, recorded; if both channels fail on a critical request → flag admin.
Jobs (persisted future calls, idempotent): wave N · check-in · release · expire (needed_by) · close-the-loop reminder (arrival+30 min) · auto-close unconfirmed (24 h) · availability expiry prompt · stale uploads · SWEEPER every minute (fixes expired-but-open requests, overdue releases, missed waves, unsent attempts). Cloud Run CPU must be always on [Likely].
Screens: S12 Requests for you (Ready ✓ valid until X; cards: urgency, group, bags, hospital, needed-by; not Ready → banner "Take today's readiness check to pledge"; list stays visible; an Off donor still sees it) · S12a detail · S13a pledge sheet (arrival chips 30 min / 1 h / 2 h / custom ≤ needed-by; ☐ share my number; Confirm; free cancel noted) · S14 pledged (hospital, arrive-by, "Still coming?" card, Call, WhatsApp, Open in Maps, I've arrived, "Hospital couldn't take my donation") · each push opens its screen.
